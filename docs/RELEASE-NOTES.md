# mycodebox release notes

The release note of this repo (owner 2026-11-13). Every merged code change (not docs-only) adds one entry at the top of
`## Unreleased`; the done-check reads the merged diff for this file (REFERENCE "Closing review"). Entry form: one line,

- **A deploy's server-restart warning no longer wakes the manager** — each queued server deploy raised it twice ("waiting up to 10 min", "restarting now") with nothing to do; it is still in the event file and the owner views, and a failed deploy still wakes urgently · area: manager

- **Open tabs pick up the play-on-tap change, and a late render stays silent** — a tab reloads only when `sw.js` changes, so tabs opened earlier kept rendering every reply; the shell cache version is bumped. Audio no longer starts if you left the reply while it rendered · area: voice

- **Read-aloud renders only when you tap play** — every reply the reader showed started a piper render (90 in 24 h) whether or not it was heard. The first tap now renders, then plays; on a browser that refuses the late start (iPhone), tap play again · area: voice

- **The read-aloud play and speed buttons work** — since 2026-10-08 the chip returned right after a successful render, before attaching their click listeners, so play did nothing · area: voice

- **Read-aloud no longer takes codebox to 100 % CPU** — piper ran with one pinned thread per core (373-470 % on 6 cores), several at once. A render is now niced (10), uses 2 onnxruntime threads and renders queue one at a time (8000 chars: 58 s, peak 199 %); the audio chip waits 10 min instead of 90 s, and a half-written WAV is no longer served as ready · area: voice

- **"Deployed" now means live: a deploy that left a leased host on old code is told as NOT live, and sessions waiting on it are woken when it is** — 117 of 273 deploy runs of 2026-11-24..25 ended `SKIPPED: RUNNING OLD CODE (restart deferred)` (vpt-pi1 ~20 times, one session held a lease for hours) and the requesting sessions still said "deployed". The runner now records which hosts each deploy skipped (`<deploys>/<id>.skipped.json`, written before the deploy is finished) and `deploy-live.js` reads the registry's active catch-up deploys: an integration is `live` only when no skipped host still waits for its catch-up, else `pending`. The line typed to the requesting session says `NOT live yet on vpt-pi1: restart deferred (lease <holder>, until ~HH:MM UTC)` and to end on `STATUS: waiting: integration <id>`; the feed title says "deployed, NOT live yet"; `GET /api/integration/requests/:id` carries `live` / `notLiveText` / `pendingHosts`, `GET /api/integration/live` lists every pending integration, and `manager-status-scan.sh` prints a `deployed-not-live` line for each. A session ending on `STATUS: waiting: integration <id>` or `deploy <id>` is not woken while the truth is pending and is woken with "now live on every host" the moment the catch-up ran (own-jobs, same wake path). The done-check pushes ONCE when a closing text claims deployed / live / in prod for an integration that is still pending ("not live on <hosts> yet; end on STATUS: waiting: deploy <id>"). The vpt-host restart rule is unchanged: it still waits for every lease. In plain words: "deployed" is only said when the new code runs on every host, and a session that waits for it is woken as soon as that is true · tests `test/deploy-live.test.js`

- **The goal check no longer rejects every reply when the goal is just a screenshot** — a goal given as an uploaded image path (`@/home/.../uploads/...png`) was split into path words the reply never names ("names 0 of the goal's words, 3 needed"), so 4 sessions looped 3-4 times on 2026-11-24/25. File paths and links are now dropped before the goal words are counted; a goal that is only attachments is restated by any reply that gives evidence (`goal-check.js` `stripAttachments`). In plain words: send a screenshot as the task, the agent is no longer asked to repeat the file name.
- **found-bug files only a bug unrelated to your task** — `--why-not-fixed` now takes only `other-area` or `live-session-task`; `large`, `host-or-device`, `credentials` and `owner-floor` exit 2 with the rule (owner 2026-11-25: a bug, leftover or idea inside your task is fixed or explained in the reply, never filed). The intake still reads old records with those reasons.

- **Archiving a session in the Claude app now removes it from the dashboard** — every 60 s ghosty lists the Remote Control sessions of each Claude account (`GET /v1/code/sessions`, the call the CLI itself makes) and acts only on `status: archived`: a codebox session is parked (resumable) by the existing auto-park checks even when its CLI missed the 4090 disconnect line, and a `mac:` row (no pane to park) is removed, matched by its Remote Control id or, else, by a title whose every listed session is archived. Idle, completed, disconnected, rate-limited or vanished sessions never trigger it; a row that posts after its archive stays. The Mac hook now sends the Remote Control URL from the transcript (exact match after the next hook install). Token: the account's own OAuth token on codebox, in memory for that GET only. Switch `manager.json` `archiveSync:false`; journal `archive-sync.jsonl` (docs/tasks/TASK-mac-archive-sync.md) · area: parking

- **Host deploys no longer end the nightly scheduled runs** — a P3 (scheduled) device lease used to yield to every queued host deploy, though the runner starts host deploys with `skip_leased` (code synced, vpt-host restart deferred to a catch-up), so every integration deploy evening ended the nightly STB campaigns (bug-4c604fc3: 11-24 21:48-00:14 UTC eight yields on vpt-pi1 / vpt-mf1, no run of the four completed in a week). Yield and the 60 min hold cap now count only a deploy whose `deploy start` would be refused by the lease (`deployWaitsOn`); between 21:00 and 03:00 UTC (`scheduledSpareWindowUtc`) a catch-up waits for a scheduled run and gates no claim meanwhile, then restarts the host when the run releases it · area: lease-service

- **The Platforms page stops showing registry junk and shortens its labels** — an env whose every ledger row was written by a `test:` agent more than 24 h ago (the `e` residue of the update_core ledger harness, which ran the live CLI before the 2026-10-24 frozen fixture) is hidden and counted in one `N test env hidden` line; a host key that is another key written twice (`vpt-wise1vpt-wise1`, recorded before the registry refused glued names, bug-2495f66e) is not a row; env and host labels drop `-vpt` / `vpt-` (`node1`, `pi1`) display-only, real names stay in titles, data and requests, never when two names would collide (`envLabel` / `hostLabel`, `public/platforms-view.js`); no ledger row is deleted · area: platforms

- **A server deploy warns, and waits up to 10 min, for the `vpt-lease run` tasks it would cut** — before a `server` / `full` deploy restarts the server, the runner names the running tasks (`server restart will lose N running task(s): <lease ids / holders>`, plan log plus a `deploy:<id>:warning` manager event), gives a progressing run up to 10 min (30 s polls) to end, then proceeds and warns again; never forced, hosts-only deploys unaffected (incident 2026-11-24: a restart lost task 3a6273b2 and its lease sat 40 min). First real server deploy that meets a vpt-lease run: check ~/.local/state/ghosty/deploys/<id>.log for the warning line (real end-to-end deploy not run: waived by manager, tests + fake-server replay) · area: deploy

- **A run that stopped progressing no longer looks active to the lease service** — `vpt-lease run` gives the wrapped command `$VPT_LEASE_PROGRESS_FILE`; `vpt_run.py` keeps its mtime at the last answer of the server. When it is older than 5 min (`VPT_LEASE_PROGRESS_STALE_S`) the heartbeat goes `active:false` with `stalled: "<task id>, server not answering"`, the idle clock stops being reset, the lease shows `stalled`, and the nudge text names `lease held, run not progressing: <task id>, server …` (incident 2026-11-24: 40 min of 502 held a device lease, heartbeating active) · area: lease
what changed and why it matters, ending with `· area: <area>`.
